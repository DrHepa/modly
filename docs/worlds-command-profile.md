# Worlds command CPU diagnostic

This diagnostic is separate from `worlds-command-latency.mjs`. Its production modules, normalizing service, controller and default-sync repository are unchanged. The diagnostic plan, summary and classification explicitly use `performanceAcceptance: NOT_ASSESSED`; raw profiles/documents keep their original formats. Completion is not latency or engine acceptance.

## Admission

From the canonical checkout, define `REPO_ROOT="/absolute/path/to/modly"` and `NODE24="/absolute/path/to/node-v24.14.1"`, then run `cd "$REPO_ROOT"` and `"$NODE24" scripts/worlds-command-profile.mjs --report-only`. This reads/hashes the inherited benchmark closure plus this diagnostic, its tests/documentation, runner and protected repository tests. Diagnostic runtime imports must already belong to the inherited closure or be built-in Node modules. No application import, profiler connection, evidence directory or workspace is created by import, help or report-only.

The report prints a distinct diagnostic seal and exact proposed argv. A fresh independent review and separate execution authorization are required before invoking that argv with `--run --seal-sha256`. Use canonical cwd, the sealed Node binary and existing empty/unset `NODE_OPTIONS`/`NODE_PATH`. Unknown arguments, extra runtime flags, different source/runtime/seal and new import edges fail closed. No workspace override, `--cpu-prof`, `--inspect`, injected loader or environment repair is supported.

## One fixed run

- Create/open with the real service and controller, then the benchmark's deterministic100-empty-entity fixture:32 setup batches followed by20 consecutive transforms, revisions33–52. The diagnostic reuses the exported fixture builder without adopting its uninstrumented/latency labels. Default repository IDs, clock, file/directory sync, canonical validation, recovery and retention are untouched.
- After setup, connect one local `node:inspector.Session`; enable `Profiler`, set1000µs sampling. Each profiled operation is bounded by awaited `Profiler.start`, monotonic start, the unwrapped controller dispatch promise, monotonic settlement, and `Profiler.stop`. No inspector TCP listener, debugger pause, precise coverage, heap profile, forced GC, global monkeypatch, failure checkpoint or sync override is used.
- A bounded read-only controller subscription records loading/ready lifecycle and revision timestamps. It performs no logging, serialization, filesystem work or mutation. Its listener failures/overflow are retained instead of disappearing behind controller listener isolation.
- Profile serialization/persistence, builders, full expected/observed snapshot assertions, full local/public receipts and actual durable-body custody happen outside CPU capture. Their cache/I/O impact is uncontrolled. Each completed mature command requires32 ledger entries and eight backups, no journal and no durability warning. A new repository/service/controller then opens the full expected revision52 snapshot with empty volatile history. Preview/retry/Undo/Redo remain covered by the separate benchmark, not rerun or claimed here.

## Interpretation

Raw per-dispatch `.cpuprofile` files are authoritative sampling evidence. Each CPU summary validates its complete node tree, sample references, finite nonnegative matching deltas and time coverage. Time deltas are sample weights in microseconds: exclusive weight belongs to the sampled leaf; inclusive weight belongs once per distinct function group on the synchronous sampled ancestor stack, including recursive groups only once. The raw tree preserves recursive frame instances. Inclusive totals overlap and are not additive. Call-frame source positions are V8 zero-based positions, not direct one-based editor links.

Idle, GC, program/unattributed, inspector, harness, dependency, runtime and application work remain separately visible. Weighted samples are estimates, not exact CPU timers or call counts. Profile envelopes contain small inspector/harness margins. They are not trimmed using an assumed common epoch with `hrtime`. The lifecycle brackets are coarse wall intervals: start→loading is queue/local preparation; loading→ready combines repository, service and post-response verification; ready→settlement is the tail. They are not exact repository timers. Idle/gaps cannot identify an individual filesystem/fsync/lock/scheduler wait.

No p95, under50ms flag, causal comparison or speedup classification is calculated. Sampling/observer overhead means these are not unprofiled benchmark observations. Same-process Node results do not prove renderer/IPC/Electron/GPU/native crash or power-loss behavior.

## Budget, partial evidence and ownership

Execution is one attempt under `/usr/bin/timeout --signal=TERM --kill-after=5s 180s`, with an internal170-second no-new-operation deadline. At most20 raw profiles and64MiB of serialized raw profile data are admitted, separately from256MiB of unique raw durable body blobs. Per-file document/pack reads are limited to16MiB, index reads to64KiB. These are diagnostic limits for this fixed fixture, not changes to product limits. Missing/empty/malformed profiles, exceeded limits or unreadable/mismatched custody are incomplete evidence, never zero CPU. No retries, extra warmups, parallel workloads or repeated attempts are allowed.

The run creates only a new0700 evidence child of `$REPO_ROOT/docs/worlds-engine-evidence/2026-09-09/current-command-cost-map/diagnostics/` and a new0700 `/tmp/modly-worlds-command-profile-new-*` root. It never reuses baseline/native/measurement roots. Metadata, sealed source manifests, full inputs/expected/observed snapshots, raw rows/profiles, lifecycle markers, reduced CPU tables, warnings, durable ledger/backups, pending commands and errors are retained. A pending command is persisted before capture so forced termination can leave an honest incomplete record.

Every settled admitted dispatch attempts actual controller state, returned result and safe durable observations even when stop, reduction, lifecycle validation or an evidence write fails. Original operation, profiler and evidence failures remain independent. A failed capture attempts unsubscribe/disconnect before durable custody; a failed disconnect remains an instrumentation-settlement error, not a valid capture boundary. Each observed record contains the full latest controller receipt and public receipt, not only their hash fields. `last-settled-actual.json` is an additional finalization capsule written before controller close, including safe observations already obtained; it does not turn missing mandatory per-command custody into completion. Unsubscribe/disconnect/close are always attempted after settlement. A hung operation/stop or forced kill can still leave only earlier/pending evidence.

Each settled inventory reads the current primary state/project/scene and all primary ledger `after/result.v1.json` bodies (including full snapshot and inverse), plus all currently retained backup state/project/scene/index/pack files. Raw bytes are hashed independently and compared to authoritative state/ledger/index hashes, pack lengths and contiguous entry ranges. The full byte blobs permit an independent semantic audit; the diagnostic's structural/hash checks do not replace production semantic validation. Coverage is the observed current ledger and retained backups per command/reopen, not all historical filesystem states or extra files outside their references.

`scene-binding.json` pins the single scene's semantic ID, logical document path and project ID from the production-validated initial snapshot. Primary, every retained backup and reopen must agree with that same binding in state, project reference and scene body. The physical filename comes only from the exact `Worlds/<projectKey>/scenes/` prefix plus the whole `scene-<32 lowercase hex>.world-scene.json` suffix. Semantic IDs are not filenames and are never hashed, punctuation-normalized or interpolated into physical paths; legal custom IDs may be independent of the random storage key.

`body-<sha256>.bin` stores identical bytes once; `body-custody.jsonl` and each disk inventory retain source-relative paths, actual hashes/lengths, blob names and opened-file identities. Bytes are freshly read and hashed for each observation, but duplicate blobs are not rewritten. Bounded nofollow opened-file reads reuse the sealed repository IO helper and check canonical parents, file type/device/inode/uid/size/timestamps before and after reading. Corrupt bytes are retained before authoritative hash comparison where possible. Bounds/IO failures leave incomplete custody and the root intact. These checks detect observed replacement, not an adversarial changed-and-restored interval; byte hashes remain the content authority.

**The one newly owned workspace is always retained by design, on success and failure.** There is no workspace deletion call or deletion option. Immediately after allocation, `workspace-provisional.json` records the path before any identity await. Failed initial identity admission preserves that exact path as `CREATED_IDENTITY_UNCONFIRMED`, never `NOT_CREATED` or fabricated ownership, with no application-command/profiler admission. `owned-workspace.json` records the confirmed original token/path/device/inode/uid, `workspace-initial.json` the initial observed directory identity, and `workspace-admission.json`/`workspace-final.json` separate observations around final evidence persistence. Matching canonical path/realpath, token and directory/non-symlink identity yield `WORKSPACE_RETAINED_BY_DESIGN`, never cleanup PASS or removed. A replacement or unverifiable identity is recorded as incomplete without modifying the replacement. Tradeoff: one small scratch fixture remains at the exact recorded path for later separately scoped cleanup. Source snapshots cannot prove absence of transient changed-and-restored source; freeze the closure throughout execution.

Exit0 means complete usable diagnostic evidence plus functional/source/settlement/retained-identity gates; exit1 means incomplete or invalid evidence. `intended-exit-code.txt` is not the actual process/timeout outcome: the independent operator envelope must retain actual argv/cwd/Git state, start/end, separate stdout/stderr and actual exit/signal. Final write failure can leave a stale/partial file; the returned error ledger and external outcome must be checked, not just one earlier summary. No result is an execution authorization.

## Unit and real-storage contract verification

Both `scripts/worlds-command-profile.test.mjs` and `scripts/worlds-command-profile.contract.test.mjs` are registered once in the governed Node runner. Direct focused invocation uses the fixed Node binary with `--experimental-strip-types --test --test-isolation=none --test-concurrency=1 --test-reporter=tap`. Unit tests use hand-computed CPU fixtures, fake application/storage/profiler workflow ports, replacement/error finalization cases and canonical-shaped in-memory reader/CAS fixtures. Actual exported pure document/command functions construct the unit fixtures; they do not execute repository commands. Fake workflow custody is not authoritative persistence proof.

The separately bounded contract test executes one real52-command default-ID project through the actual controller, normalizing service, default-sync repository, diagnostic reader and CAS, plus four one-command custom-ID projects in one additional newly owned workspace. Only its profiler is synthetic. Its test name and durable wrapper explicitly label `SYNTHETIC_PROFILER_FOR_CONTRACT_ONLY` and `NOT_CPU_EVIDENCE`; synthetic raw profiles must never be interpreted as CPU evidence. It audits actual primary/result/revision0-empty-pack bytes, mature32-ledger/eight-backup custody, revision52 fresh-open empty history, independent custom IDs/keys, and exported canonical receipt contracts (UTF-16 FNV, object sorting, array order, payload no LF versus stored result one LF). Tests retain new workspace identities and bounded body blobs under a unique `storage-binding-remediation/contract-tests/` evidence child, never the actual operator/diagnostics namespace, and never delete their workspaces. Use a separately authorized150-second outer bound for the contract test; unit tests are bounded to60seconds. The contract test input and its checked import edges are sealed alongside the inherited closure; its only runtime substitution is the synthetic profiler and test evidence destination. Neither these tests nor report-only readiness prove real profiler compatibility or performance. Port injection is an exported test seam, not a CLI option or production hook.
